🔒 X-Content-Type-Options Header Detection Tests

Regression tests for false-positive fix in security scanner detection of x-content-type-options header.

Test Summary

1. Case-Insensitive Header Name Detection

Tests that the scanner correctly identifies the header regardless of case variations.

Test 1.1: Header name "X-Content-Type-Options" (Title Case)

Response Headers:
X-Content-Type-Options: nosniff

Expected: Header detected as PRESENT (no vulnerability reported)

Test 1.2: Header name "x-content-type-options" (lowercase)

Response Headers:
x-content-type-options: nosniff

Expected: Header detected as PRESENT (no vulnerability reported)

Test 1.3: Header name "X-CONTENT-TYPE-OPTIONS" (UPPERCASE)

Response Headers:
X-CONTENT-TYPE-OPTIONS: nosniff

Expected: Header detected as PRESENT (no vulnerability reported)

2. Case-Insensitive Value Detection

Tests that the scanner correctly validates "nosniff" value regardless of case.

Test 2.1: Value "nosniff" (lowercase)

Response Headers:
X-Content-Type-Options: nosniff

Expected: Value accepted as valid (compliant)

Test 2.2: Value "Nosniff" (Title Case)

Response Headers:
X-Content-Type-Options: Nosniff

Expected: Value accepted as valid (compliant)

Test 2.3: Value "NOSNIFF" (UPPERCASE)

Response Headers:
X-Content-Type-Options: NOSNIFF

Expected: Value accepted as valid (compliant)

Test 2.4: Value with leading/trailing whitespace " nosniff "

Response Headers:
X-Content-Type-Options:   nosniff

Expected: Value accepted as valid after trimming (compliant)

Test 2.5: Invalid value "nosnif" (typo)

Response Headers:
X-Content-Type-Options: nosnif

Expected: Weak configuration reported (invalid value)

3. Redirect Response Handling (302 → 200)

Tests that the scanner evaluates only the final response in redirect chains.

Test 3.1: 302 Redirect Response (should NOT be evaluated)

Response: 302 Found
Location: /new-location
X-Content-Type-Options: (absent)

Expected: NOT flagged (redirect response, not final)

Test 3.2: 301 Permanent Redirect (should NOT be evaluated)

Response: 301 Moved Permanently
Location: /permanent-location
X-Content-Type-Options: (absent)

Expected: NOT flagged (redirect response)

Test 3.3: Final 200 OK with header present

Response: 200 OK
X-Content-Type-Options: nosniff

Expected: Header PRESENT (compliant)

Test 3.4: Final 200 OK without header

Response: 200 OK
X-Content-Type-Options: (absent)

Expected: Header MISSING (vulnerability reported)

4. HTTP/2 and Gzip Response Handling

Tests that HTTP/2 framing and gzip encoding do not affect header detection.

Test 4.1: HTTP/2 Response with lowercase headers

HTTP/2 200 
content-type: application/json
x-content-type-options: nosniff
content-encoding: gzip

Expected: Header detected as PRESENT (HTTP/2 uses lowercase)

Test 4.2: Gzipped response body (header still readable)

HTTP/1.1 200 OK
Content-Encoding: gzip
X-Content-Type-Options: nosniff
[gzip-compressed body]

Expected: Header detected as PRESENT (body encoding doesn't affect headers)

5. Various Response Status Codes

Tests that headers are evaluated for all response types.

Test 5.1: 404 Not Found with header

Response: 404 Not Found
X-Content-Type-Options: nosniff

Expected: Header PRESENT (compliant)

Test 5.2: 500 Internal Server Error with header

Response: 500 Internal Server Error
X-Content-Type-Options: nosniff

Expected: Header PRESENT (compliant)

Test 5.3: 403 Forbidden without header

Response: 403 Forbidden
X-Content-Type-Options: (absent)

Expected: Header MISSING (vulnerability)

6. Header Absence Detection

Tests that truly missing headers are correctly flagged.

Test 6.1: Header completely absent

Response: 200 OK
Content-Type: application/json
[No X-Content-Type-Options header]

Expected: Header MISSING (vulnerability reported)

Test 6.2: Empty header value

Response: 200 OK
X-Content-Type-Options:

Expected: Weak configuration (empty value is invalid)
